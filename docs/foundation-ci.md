# Foundation CI

The [foundation workflow](../.github/workflows/foundation.yml) runs on pushes, pull requests and manual dispatch using Ubuntu 24.04, Python 3.13 and the exact SDK from [global.json](../backend/global.json). Repository permissions are read-only. It runs the retained contract runner and backend component runner, including local signer subprocess tests, enrollment HTTP pipeline tests, separate loopback Kestrel TLS tests and compilation of the PostgreSQL test project. Backend checks still run when contract validation fails. A failed check fails the job; no test failure is converted to success.

The final upload step runs even after failure and retains source snapshots, manifests, commands, dependency versions, TRX and HTML replays for thirty days. Generated .NET `bin`/`obj` trees are excluded. Existing checked-in historical evidence is included; identify the new run by its timestamp and manifest rather than assuming every bundled replay passed. Interrupted/cancelled execution may produce incomplete evidence. GitHub artifact retention is not permanent archival; locally published evidence remains in Git. CI does not generate browser screenshots.

No repository secrets or private lab keys are required. Process tests generate their own transient CA keys and pass them through redirected stdin, never the artifact tree. Administrator tests generate ephemeral signing keys and use explicit validation or simulated discovery metadata; no live identity provider is contacted. Third-party actions use maintained major-version tags; immutable action SHA pinning and dependency lockfiles are future hardening, not claimed supply-chain guarantees.

## Remaining MVP Work

The host-side [MQTT mTLS/ACL lab](mqtt-device-lab.md) narrows the transport gap to real enrolled-device/backend integration, authenticated backend publishers/ingestion, durable delivery and session/lifecycle controls. Its explicit lab membership is not a replacement for PostgreSQL enrollment or audited access management.

The [HTTPS device identity follow-up](device-mtls.md) now has local API 34/Kestrel/PostgreSQL mTLS and persisted-disable evidence. Hosted CI covers its component/loopback and JVM tests, not emulator runtime. The older generic device-mTLS gap below is narrowed to MQTT mTLS, lifecycle/revocation workflows and deployment hardening; no full fleet acceptance is implied.

The enrollment foundation is not the full portfolio MVP. The [enrollment HTTP lab](enrollment-http.md) implements strict body handling, bootstrap bearer authentication and process-local rate limits. The [administrator route](administrator-enrollment.md) validates API access tokens and permissions, commits a minimal actor audit atomically and delivers pending-enrollment secrets once. The [combined API 34 enrollment harness](android-enrollment.md) now verifies Keystore enrollment over actual HTTPS against PostgreSQL and the lab signer. Remaining acceptance work includes browser OIDC login and live identity-provider integration; secure production token transfer to Android; device mTLS; durable Room inbox/outbox and HTTPS reconciliation; backend event ingestion, full audit and transactional outbox; signed resumable APK delivery and installation recovery; the management console; reproducible infrastructure; and end-to-end offline/security/load tests. Production enrollment still needs distributed abuse controls, production CA/key management and revocation. Current-stable Android compatibility remains deferred and unpassed. The [project plan](../PROJECT_PLAN.md) remains prospective, with no progress status inserted into it.
